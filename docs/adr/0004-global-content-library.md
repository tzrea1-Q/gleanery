# 内容库全局唯一，数据集只存成员关系

同一条内容（以及它的评论、作者、字幕）按"平台 + 平台内 ID"在全应用只存一份，称为内容库；数据集不复制数据，只记录"包含哪些内容"（`dataset_item`），评论和字幕挂在内容上，数据集的评论就是其内容的评论。再次采到同一条内容时就地合并（非空覆盖、完整度只升不降、互动数另留快照历史）。之所以不让每个数据集各存一份副本：单用户本地应用里，用户期望"同一条笔记在哪里看都一样"，副本会让同一条笔记在两个数据集里互动数、评论数各不相同，也重复存储、重复去重。

## Considered Options

- **每个数据集各存一份副本**：数据集冻结在采集时刻、去重只在数据集内、删除最简单；代价是同一内容多份且彼此不一致。被否。

## Consequences

- 在数据集 B 补采某条内容后，数据集 A 里同一条内容的评论和互动数也会变多、变新。需要"当时的样子"时，看报告（报告保存自己的文字）或互动数快照。
- 删除数据集只删成员关系与它的采集任务；不再属于任何数据集的内容要在同一事务里回收，否则内容库会无限增长。
- Agent 的只读 SQL 只查一组视图（`v_contents`、`v_comments`、`v_subtitles`、`v_datasets`），视图按数据集过滤、把常用 ext 字段展开成列。视图是对 Agent 的契约：改表时必须保持视图兼容，不能让 Agent 直接依赖底层表。
