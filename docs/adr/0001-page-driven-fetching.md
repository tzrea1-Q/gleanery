# 采集取数走页面驱动，不自带逆向签名

采集层在应用管理的专用 Chrome 里导航、滚动页面，由平台自己的页面 JS 加签并发请求，应用只拦截页面收到的响应（`page.on('response')`）；项目中不包含小红书 x-s、B 站 WBI 等签名算法，也不依赖 xhshow 之类的第三方纯算法库。原因：B 站已对 `bilibili-API-collect`、`bilibili-api` 发律师函，点名"绕过反爬风控与签名鉴权"；小红书风控持续收紧，浏览器外 httpx 请求的 TLS/HTTP 指纹与浏览器不一致；页面驱动最接近真人使用，而本应用的保守限速（每条 6–15 秒）使"慢"不构成实际代价。

## Considered Options

- **xhshow 纯算法签名 + httpx 浏览器外发请求**（MediaCrawler 现行做法）：最快、浏览器只提供 Cookie；但项目自带逆向签名、需跟进第三方库版本、指纹不一致。被否。
- **在页面里调用站点自带签名函数**（`_webmsxyw` → `mnsv2`）：函数名已变过两次，最脆弱。被否。

## Consequences

- 采集执行时浏览器必须在线，平台适配依赖页面结构与 URL，页面改版即需更新适配。
- 取数做成可插拔 `Fetcher` 接口；若页面驱动在实测中走不通，回到本决策重新评估，而不是悄悄换成签名库。
