# 监控规则只在创建时确认，无人值守时只能减少平台访问

监控规则由用户确认一次，之后每次到点自动生成采集任务，不再逐次确认。这沿用 [ADR-0005](0005-agent-has-no-direct-fetch-tools.md) 的思路：审批放在创建规则时。代价是规则运行时往往没人看着，所以无人值守的环节只能减少平台访问，不能增加：

- Agent 可以起草规则、列出规则、暂停规则；确认、恢复、删除只能由用户在界面上操作。
- 某次运行因风控、锁定或登录失效而失败，规则自动暂停，等用户手动恢复。冷却会自动到期，规则不会。
- 运行结束后不会自动让 Agent 整理新内容，由用户点按钮触发。
- 应用没开时错过的运行，下次启动时每条规则最多补跑一次，不会把错过的每一次都补上。

这样定，原因有二：
- 每次平台访问都用到用户的账号，并消耗风控余量。用户不在场时，连续撞上风控的代价最大，也最难察觉。
- 自动整理会在用户不在时消耗模型额度，还会在对话里冒出用户没有发起的回复。

## Considered Options

- **每次运行都请用户确认**：最安全，但每天都要点一次，等于没有监控。被否。
- **风控后只冷却，规则照常运行**：省去手动恢复，但无人值守时会一次次撞墙。被否。
- **运行后自动让 Agent 整理**：最省事，但会悄悄消耗额度。暂不做，以后可以让规则选择是否开启。
- **把错过的运行逐次补跑**：应用一启动就会连续访问平台。被否。

## Consequences

- 规则暂停后要靠用户发现，所以自动暂停时发浏览器通知，规则卡片上也写明原因。
- Agent 的工具里没有恢复规则、确认规则的操作。用户让 Agent "恢复监控"时，它只能告诉用户去哪里点。
