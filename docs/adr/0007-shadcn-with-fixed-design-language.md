# 界面用 shadcn/ui 加一套固定的设计语言，业务代码不手写控件

界面组件用 shadcn/ui（Radix，`new-york` 风格），组件代码放在仓库里。设计语言是灰色画布、白色悬浮面板、墨黑主按钮，颜色只表达状态。业务代码手写控件过不了 lint。具体规则见[前端界面规范](../frontend.md)。

这样定，原因有三：
- 早期界面是手写控件拼的，每处的按钮、输入框和错误提示都不一样，改一处不会带动别处。
- 这是个数据密集的工作台，用户要长时间看表格和报告。状态颜色足够克制，才能一眼看出哪里要处理。
- 组件代码在仓库里，可以按设计语言改外形，也不用为此多一层运行时依赖。

## Considered Options

- **继续手写控件，只整理样式**：不用加依赖，但无障碍、键盘操作和弹层都要自己维护。被否。
- **换成样式写死的组件库**：开箱即用，但外形由库决定，要做出这套设计语言得和库对抗。被否。
- **暖白底、蓝色主色**：先实现过一版，方向可用，但层次靠描边，精致感不够。被灰底白面板取代。
- **引入 `Resizable`、`Command`、`Calendar` 这类组件**：都要加依赖，现有需求用不上这么多。工作区拖动条手写，日期用原生输入。

## Consequences

- Radix 的 `Select` 不是原生控件：测试要先打开再选，`required` 和 `fieldset disabled` 都不生效，要自己处理。
- 升级 shadcn 组件时要保住我们对生成代码的改动，这些改动列在规范里。
- 项目没有截图回归，风格一致靠 lint 拦控件和颜色，其余靠规范的完成标准走查。
