# 监控开发契约

这一档实现**监控规则**：按周期自动执行的采集计划，用来发现关键词下的新内容。从 `main` 开始，不编号，就叫"监控"。

本文记 2026-11-08 定下的决定，以及切片和验收标准。术语见 `GLOSSARY.md` 的"监控规则"，无人值守的边界见 [ADR-0008](../adr/0008-monitoring-unattended-only-reduces-access.md)。文件归属和共享件由开发会话读过代码后补进本文。

## 1. 已有基础

- `collection_task` 已有 `trigger`（目前只有 `conversation`）和可空的 `schedule_rule_id`。
- ADR-0005：监控规则是"计划模板 + 周期"，审批发生在创建规则时。
- 已采过的内容按"已满足"跳过，跳过的也算进任务数量。
- 应用重启时，进行中的任务变成"已中断"，等用户续跑。
- 浏览器通知已有（`frontend/src/lib/notify.ts`），页面开着但不在前台时发，目前只用于风控。
- 有运行中的任务时，数据集不能删除（`DATASET_HAS_ACTIVE_TASKS`）。

## 2. 决定

### 范围

1. **只盯关键词下的新内容。** 跟踪指定内容的互动数和评论变化不做。
2. **周期只有"每天"和"每周"**，时间点由用户选，按本地时间。最短一天一次。
3. **B 站和小红书都开放。** 知乎上线后自动适用。

### 规则

4. **创建**：用户在对话里提需求，Agent 起草一份带周期的计划，用户在计划卡片上点"创建监控规则"确认。之后到点生成采集任务（`trigger = schedule`），不再逐次确认。
5. **管理**：规则可暂停、恢复、删除。改关键词、数量、深度或周期都要起草新草稿并重新确认；确认后仍是同一条规则，版本号加一，数据集和运行记录保留。
6. **归属**：规则独立于对话，只记下创建它的对话。删除对话不影响规则。
7. **数据集**：每条规则绑定一个数据集，每次运行都追加进去。有规则绑定时（包括已暂停的），数据集不能删除，提示先删规则。
8. **条数**：不限规则条数。确认新规则时，按所有生效规则的每日预计量校验：某个平台的合计超过该平台每日额度的一半，就不让确认，并说明原因。

### 每次运行

9. **怎么取**：排序固定为"最新"，平台时间筛选取能覆盖"上次成功运行至今"的最小一档，这两项用户不能改。
10. **取多少**：数量是每个平台单次运行的上限，默认 20，最多到该平台单个任务的默认数量。已采过的也算在内；上限内全是新内容时，提示"可能还有更多新内容"。
11. **采多深**：可选全部深度，默认只要"详情"。选了评论时，确认卡片写明预计请求量。
12. **队列**：和手动任务走同一个队列，共用每日额度和任务间隔。到点时：
    - 前面有任务在跑或在间隔里：排队等。
    - 冷却中：冷却结束后当天照跑。
    - 今日额度用尽：这一次跳过并记下原因，规则不暂停。
    - 需要登录或已锁定：规则暂停。
13. **风控**：某次运行因风控、锁定或登录失效而失败，规则自动暂停，标出原因，等用户手动恢复（ADR-0008）。
14. **应用没开时**：启动时，每条规则最多补跑一次，时间范围从上次成功运行算起，错过几次都合并成这一次。不做后台常驻。
15. **中断**：监控任务因应用重启而中断时不续跑，按"错过的运行"处理，由下次启动的补跑覆盖。因风控而中断的按第 13 条处理。
16. **运行记录**：每次到点都记一行，包括被跳过的：时间、正常运行还是补跑、各平台的采集任务、新增条数、跳过原因。规则详情显示最近 30 次，不设清理期限。每次运行用的规则版本，由采集任务的计划快照记录。

### 新内容与提醒

17. **"新增"**：这次运行中第一次进入该规则数据集的内容，不管之前在不在内容库里。
18. **提醒**：多次运行的新增条数累加，直到用户打开这条规则的新增列表才清零。新增列表是只看这些内容的数据集视图。
19. **通知**：有新内容只在应用内提醒：左栏监控入口显示未读数，规则卡片标出"新增 N 条"。规则自动暂停时发浏览器通知，文案写明是哪条规则。
20. **整理**：运行后不自动让 Agent 整理。规则卡片上有"让 Agent 整理"按钮，点了才在创建规则的对话里开始。规则可以记一句后续意图，作为点按钮时的默认要求。

### Agent

21. **工具**：`propose_collection_plan` 加一个可选的周期，带周期的草稿就是监控规则的草稿；修改规则也是起草新草稿。新增两个工具：列出规则、暂停规则。没有恢复、删除、确认规则的工具（ADR-0008）。
22. **系统提示**：由开发会话定稿，不派给 Codex。

### 界面

23. **监控页面**：独立页面，左栏放入口并显示未读数，骨架和平台账号页相同。每条规则一张卡片：关键词、平台、周期、下次运行时间、上次结果、新增条数，暂停时写明原因。
24. **计划卡片**：现有计划卡片多一个"周期"字段，确认按钮改为"创建监控规则"。

## 4. 验收

- `just ci` 退出码 0。
- 测试覆盖：到点计算（每天、每周、跨日）、启动补跑只跑一次且时间范围正确、额度用尽跳过并记录、风控和登录失效时自动暂停、冷却后当天照跑、重启中断按错过处理、每日预计量超过一半时拒绝确认、"新增"的计数和清零、有规则绑定时数据集删除被拦。
- 界面按 `docs/frontend.md` 的完成标准，在 1440 和 1024 宽度、亮色和暗色下都实际看过。

## 5. 真站冒烟

用小号，B 站和小红书各建一条每天运行的规则，各 10 条，只要详情，连续跑 3 天。其中一晚关掉应用，第二天启动时验证补跑。

- 风控事件为 0。
- 新增条数和数据集的实际变化对得上。
- 额度用尽或冷却的情况被正确记录。真站不一定会遇到，没遇到就靠测试覆盖，并如实记下。

一出现风控信号就停，不重试，不调低限速。冒烟记录涉及真账号，不进仓库，由维护者另存。
